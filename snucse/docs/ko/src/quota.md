# 리소스 쿼터

만들 수 있는 자원의 양은 계정마다 **리소스 쿼터**로 정해져 있습니다. 쿼터를 넘기는 요청은 거부됩니다. 쿼터는 웹 UI의 **쿼터 신청** 메뉴에서 신청하고, 운영진(Bacchus)이 승인합니다.

## 쿼터 항목

| 항목 | 무엇을 세나 |
| --- | --- |
| vCPU (GPU 없는 인스턴스) | CPU 인스턴스의 vCPU 합 |
| 메모리 (GPU 없는 인스턴스) | CPU 인스턴스의 메모리 합 |
| 스토리지 (GiB) | 모든 볼륨(운영체제 디스크와 데이터 디스크), 남긴 루트 디스크, 디스크 이동의 이전 복사본(`-previous-`), 스냅샷, 다운로드하려고 꺼낸 볼륨 사본의 크기 합([볼륨과 스냅샷](volume.md)) |
| GPU 종류별 장수(`a100-40g`, `a100-80g`, `a6000`, `gtx1080`) | GPU 인스턴스의 GPU. GPU 1장마다 그 종류의 vCPU와 메모리가 함께 딸려 옵니다 |

- CPU 인스턴스와 GPU 인스턴스는 따로 셉니다. GPU 쿼터에 딸린 vCPU와 메모리는 GPU 인스턴스에만 쓰이고 CPU 인스턴스에는 쓸 수 없습니다. 반대로 CPU 인스턴스의 vCPU·메모리 쿼터는 GPU 인스턴스에 쓰이지 않습니다.
- GPU 쿼터는 종류마다 따로입니다. A100 40GB와 A100 80GB도 다른 종류입니다. 같은 종류라면 연결 방식(`nvswitch`, `nvlink`)과 상관없이 같은 쿼터를 씁니다.
- 인스턴스 수와 볼륨 수는 따로 신청하지 않습니다. 위 항목에 맞춰 정해집니다.
- 스냅샷 개수에는 제한이 없고, 스냅샷이 차지하는 용량은 스토리지 쿼터에 들어갑니다. 스냅샷은 만들 때마다 볼륨 전체를 복사하므로 정기 스냅샷처럼 쌓이는 스냅샷은 쿼터를 많이 쓸 수 있습니다([볼륨과 스냅샷](volume.md)). 대시보드의 **스토리지 쿼터**는 이렇게 하나로 합친 쿼터의 남은 양입니다("볼륨과 스냅샷이 이 쿼터를 함께 씁니다").
- 정지된 인스턴스도 쿼터를 그대로 차지합니다. 쓰지 않는 인스턴스와 볼륨, 스냅샷은 삭제해 주세요. 휴지통은 없어서 삭제하면 바로 사라지고 쿼터가 돌아오며, 되돌릴 수 없으니 필요한 데이터는 미리 옮겨 두세요([인스턴스 삭제와 루트 디스크](instance.md#인스턴스-삭제와-루트-디스크)).
- 현재 사용량과 한도는 로그인 후 첫 화면(대시보드)의 자원 카드에서 볼 수 있습니다.

## 기본 쿼터

모든 계정에는 운영진이 정한 기본 쿼터가 있고, 기본 쿼터는 만료되지 않습니다. 베타 기간에는 기본 쿼터가 모두 0이라 신청해야 인스턴스를 만들 수 있습니다. GPU의 기본 쿼터는 늘 0이라 GPU는 신청해야만 쓸 수 있습니다.

## 쿼터 신청

1. 왼쪽 메뉴의 **쿼터 신청 → 내 신청**에서 **새 신청**을 누릅니다.
2. 필요한 양(vCPU, 메모리, 스토리지, GPU 종류별 개수), **만료일**, **이유**를 적고 **보내기**를 누릅니다. 이유에는 용도(수업, 연구, 개인 프로젝트 등)와 기간을 적어 주세요. GPU 칸에는 지금 신청할 수 있는 GPU 종류가 모두 나옵니다.
3. 운영진이 승인하거나 거부합니다. 운영진은 값과 만료일을 조정해 승인할 수 있고, 신청 목록에는 **신청 내용**과 **승인된 내용**이 나란히 나옵니다. 승인되면 쿼터가 바로 바뀝니다.

- 결정을 기다리는 신청은 한 번에 하나만 둘 수 있습니다. 내용을 바꾸려면 **신청 취소**를 누른 뒤 다시 신청하세요.
- 목록 위의 **현재 적용 중인 쿼터**에서 지금 쿼터를 볼 수 있습니다.
- 받은 승인이 더 필요 없으면 **반납**할 수 있습니다. 쿼터는 그 승인을 빼고 다시 계산됩니다.

## 승인이 여러 개일 때

승인마다 만료일이 있고, 만료되지 않은 승인이 여러 개면 **항목마다 가장 큰 값**이 쿼터가 됩니다. 더하지 않습니다. 기본 쿼터도 이 계산에 들어갑니다.

예를 들어 12월 31일까지 vCPU 8개·스토리지 200 GiB를 받고, 11월 30일까지 vCPU 4개·A6000 1장을 따로 받았다면 11월 30일까지는 vCPU 8개·스토리지 200 GiB·A6000 1장이고, 그 뒤로는 vCPU 8개·스토리지 200 GiB입니다.

## 만료와 갱신

- 승인은 만료일 당일 23:59:59(운영진이 정한 시간대, 지금은 한국 시간)에 끝납니다.
- 만료 7일 전과 1일 전(운영진이 정한 값)에 화면 위쪽에 안내가 나오고 이벤트가 남습니다. 메일 알림은 준비되는 대로 함께 보냅니다.
- 계속 쓰려면 안내의 **갱신 신청**이나 내 신청 목록에서 그 승인의 **갱신 신청**을 누릅니다. 그 승인의 값으로 채워진 새 신청이 열리고, 다시 승인을 받아야 합니다. 이미 만료된 승인도 갱신 신청할 수 있습니다.

승인이 만료되거나 운영진이 회수해서 쓰고 있는 양이 쿼터를 넘게 되면 이렇게 됩니다.

- 실행 중인 인스턴스는 정지할 때까지 그대로 돌아갑니다. GPU 인스턴스는 지금의 사용 기한이 끝나면 정지되고, 기한 갱신은 거부됩니다([GPU 인스턴스의 사용 기한](instance.md#gpu-인스턴스의-사용-기한)).
- 정지된 인스턴스는 시작할 수 없습니다("쿼터가 만료되었거나 이 오퍼링에는 부족합니다"). 운영진의 점검이 끝나 인스턴스가 다시 시작될 때도 쿼터를 넘은 인스턴스는 정지된 채로 남습니다.
- 볼륨이나 스냅샷 만들기, 디스크 이동처럼 새로 자원을 쓰는 일은 쿼터 아래로 내려올 때까지 거부됩니다.
- 아무것도 삭제되지 않습니다. 디스크와 스냅샷은 그대로 남습니다. 쓰지 않는 볼륨과 스냅샷을 지워(되돌릴 수 없습니다) 쿼터 아래로 내리거나, 쿼터를 다시 신청하세요.
